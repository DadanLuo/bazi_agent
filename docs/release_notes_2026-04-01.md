# 2026-04-01 更新说明

## 本次更新概览

本次更新围绕三个目标展开：

1. 修复主流程不可用问题，确保八字分析、塔罗占卜、前端交互都能正常工作。
2. 提升 RAG 检索可用性，减少过严过滤和脏数据带来的低质量召回。
3. 修正排盘严谨性问题，尤其是月柱计算必须按节气切月，而不是按公历月份直接推算。

## 前端更新

- 重做首页为八字 / 塔罗双 Tab 工作台。
- 移除旧版失效的聊天式入口，不再调用不存在的 `/api/v1/chat/chat`。
- 增加八字与塔罗结果缓存，切换 Tab 时保留上一次分析结果。
- 为八字和塔罗分别补充追问输入区，前端会复用后端返回的 `conversation_id` 发起多轮对话。

## API 与会话更新

- 八字分析接口新增 `conversation_id` / `user_id` 入参，响应中返回 `conversation_id`。
- 新增八字追问接口：`POST /api/v1/bazi/followup`
- 新增塔罗分析接口：`POST /api/v1/tarot/analyze`
- 新增塔罗追问接口：`POST /api/v1/tarot/followup`
- 接入 `SessionContext`，将分析结果与追问上下文真正落盘，支持 Redis 不可用时走文件持久化。
- FileStorage 新增 UnifiedSession 读写能力，避免只保存旧格式数据导致多轮对话失效。

## RAG 检索更新

- 标准八字主链路接入 metadata `where` 过滤。
- 检索策略升级为多路召回：
  - 命局路由
  - 格局路由
  - 用神路由
- 每一路查询先走精确过滤，命中不足时自动逐层放宽过滤条件。
- 多路结果统一去重并做启发式 rerank，最终保留更高质量的片段。
- 排除 `treelist.txt` 这类非知识正文文件进入索引。
- 删除了当前 Chroma 集合中已存在的 `source=treelist` 脏数据。

## 塔罗链路更新

- 补齐 DashScope LLM 的 `call_with_tools` / `acall` / `acall_with_tools`。
- 修复 DashScope `tool_calls` 响应解析兼容性问题。
- 塔罗占卜现已支持：
  - 选牌阵
  - 抽牌
  - 单牌解读
  - 综合解读
  - 多轮追问
- `/api/v1/tarot/analyze` 和 `/api/v1/tarot/followup` 已加入 LLM 慢路径超时配置，避免 30 秒被普通超时中间件截断。

## 排盘严谨性更新

- 当前排盘实现已切换为优先使用 `lunar-python` 进行四柱计算。
- 修复月柱按公历月份直接推算的问题，改为按节气切月。
- 已验证案例：
  - 输入：`2002-10-12 21:31`
  - 修正后四柱：`壬午 / 庚戌 / 癸丑 / 癸亥`
- 已验证立春边界：
  - `2002-02-03 23:00` -> `辛巳年 辛丑月`
  - `2002-02-04 20:00` -> `壬午年 壬寅月`

## 新增测试

- `tests/test_bazi_calendar_accuracy.py`
  - 验证节气切月
  - 验证立春切年边界

## 依赖更新

  - `lunar-python>=1.4.0`

## 已知说明

- 完整八字分析和塔罗占卜都属于 LLM 慢路径，请求耗时会明显高于简单接口。
- 当前真太阳时修正仍有继续增强空间；本次重点先修正了节气切月与四柱严谨性。
